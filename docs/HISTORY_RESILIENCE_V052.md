# v0.52: preserve successful history pages on HTTP 429

Device log ChatGPT551Repair(4)(3).log confirms v51 Pin and Unpin both HTTP 200 (13:13:29 and 13:13:35 UTC). Native history succeeds through 13:13:35, then fails repeatedly with HTTP 429 from 13:13:41 through the subsequent app restart. Extra v50 title requests are absent. Removing them was insufficient to prevent existing native refresh traffic from reaching the limit.

Implementation: wrap the existing history completion path (including the companion protocol's inner completion-handler session). Save exact bytes only for valid HTTP 200 JSON objects containing an items array. On HTTP 429 only, supply a matching last-successful page and a marked HTTP 200 response to the existing consumer. No new URLSession task, retry, account mutation or chat navigation change. Real successful empty pages remain authoritative. Other statuses/errors pass through, including authentication failures.

Cache identity hashes the Authorization value, account/org/project headers, host, path and every sorted query parameter. Reads fall back to configured session headers. Headerless requests get no shared cache. Tokens are not stored or logged. Token changes conservatively get separate keys. Cache is app-local in Library/Caches/ChatGPT551HistoryPages, protected until first unlock, atomic, at most 32 pages, with a six-hour fallback expiry. Exact page queries isolate pagination/search/filter requests. Cached titles may be stale during rate limiting; successful network results replace them. No cached page means original error passes through. Requires at least one successful load after installation to seed the cache. A current existing rate limit cannot be cleared by this build.

Validation: compile and signed Mach-O page/layout checks; ARM64 bridge validation; Pin/Unpin request and menu source identical to v51; original history adapter, native opening and pinned layout source unchanged. iOS runtime and rate-limit recovery not exercised locally. Logs distinguish page_saved, last_successful_page_restored, matching_page_unavailable and authenticated_cache_key_unavailable.
